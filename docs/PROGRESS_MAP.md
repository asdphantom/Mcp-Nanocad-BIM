## Подтверждённо сделано

| Область | Состояние и доказательство |

Реализовано в [b06a496](https://github.com/asdphantom/Mcp-Nanocad-BIM/commit/b06a496); в матрице SDK отмечена успешная проверка в запущенном nanoCAD. Это не 3D solid. |

## Частично готово и ограничения

- `wall_type` и `level` есть в контракте `create_bim_wall`, но C# сервис явно отклоняет непустые значения: соответствие свойствам SDK ещё не проверено. Используйте координаты, `base_z`, `height` и `thickness`. Верхняя отметка задаётся как `base_z + height`; отдельного поля `top_z` пока нет.
- Окно вставляется по точному имени из `list_bim_windows` и handle уже созданной нативной стены. Каталог фильтрует названия с `Окно`; полноту каталога по всем типам проёмов ещё не проверяли.
- Нативные инструменты требуют загруженный .NET плагин внутри BIM Строительство 26. Python COM fallback создаёт лишь DWG-геометрию. Команды `create_wall_solid` и `complete_window_opening` не являются нативными BIM-объектами.
- Переключение 3D-вида через прежний .NET endpoint отключено для установленной редакции после аварийного завершения приложения; вид меняется в UI nanoCAD.
- Перечень остальных групп SDK и их статус уже ведётся в [SDK_COMPATIBILITY.md](SDK_COMPATIBILITY.md). В частности, уклонные крыши, редактирование контуров, оси, материалы, управление проектом, конструкции, армирование и параметрические объекты ещё не реализованы как проверенные нативные MCP-инструменты.

## Точка продолжения

1. Начать с `wall_type` и `level`: изучить публичные типы `ncBIMSmgd.dll` и примеры SDK 26, установить точное соответствие типу стены и этажу. Не подменять неизвестное свойство геометрией или DWG-слоем.
2. Добавить соответствие в `BimWallService`, обновить DTO/описание MCP и тесты. Для `top_z` достаточно валидировать `top_z > base_z` и переводить его в `height`, если этот вариант API нужен.
3. Собрать плагин, проверить стену с типом и уровнем в отдельном тестовом DWG, затем проверить открытие и сохранение чертежа. После живой проверки обновить [матрицу SDK](SDK_COMPATIBILITY.md).
4. Следующим отдельным этапом выбрать одну из ещё не реализованных групп SDK из матрицы, прежде всего уклонные крыши или редактирование контуров.

Минимальный проверяемый вызов MCP сейчас:

```json
{"name":"create_bim_wall","arguments":{"x1":0,"y1":0,"x2":6000,"y2":0,"base_z":0,"height":3300,"thickness":300}}
```

Ожидается `success: true`, `entity_type: "LinearBuildingWall"` и непустой `handle`.
Инструкции сборки и подключения DLL: [README.md](../README.md#2-установка-net-плагина).
