## Частично готово и ограничения

- При первой проверке `/api/document/new` с `save_path` сохранял прежний документ: `CadContext.RefreshDocument()` вызывался на HTTP потоке, где `MdiActiveDocument` может быть `null`. Исправление перемещает обновление ссылки на главный поток nanoCAD. Исправление собрано, но его отдельная живая проверка требует перезапуска с новой DLL.
- `wall_type` и `level` есть в контракте `create_bim_wall`, но C# сервис явно отклоняет непустые значения: соответствие свойствам SDK ещё не проверено. Используйте координаты, `base_z`, `height` и `thickness`. Верхняя отметка задаётся как `base_z + height`; отдельного поля `top_z` пока нет.
- Окно вставляется по точному имени из `list_bim_windows` и handle уже созданной нативной стены. Каталог фильтрует названия с `Окно`; полноту каталога по всем типам проёмов ещё не проверяли.
- Нативные инструменты требуют загруженный .NET плагин внутри BIM Строительство 26. Python COM fallback создаёт лишь DWG-геометрию. Команды `create_wall_solid` и `complete_window_opening` не являются нативными BIM-объектами.
- Переключение 3D-вида через прежний .NET endpoint отключено для установленной редакции после аварийного завершения приложения; вид меняется в UI nanoCAD.
- Перечень остальных групп SDK и их статус уже ведётся в [SDK_COMPATIBILITY.md](SDK_COMPATIBILITY.md). В частности, уклонные крыши, редактирование контуров, оси, материалы, управление проектом, конструкции, армирование и параметрические объекты ещё не реализованы как проверенные нативные MCP-инструменты.

## Точка продолжения

1. Перезапустить nanoCAD с последней DLL и отдельно проверить исправление `/api/document/new` + `save_path`: сразу после создания и сохранения нового чертежа повторно открыть его и сверить объекты.
2. Затем вернуться к `wall_type` и `level`: изучить публичные типы `ncBIMSmgd.dll` и примеры SDK 26, установить точное соответствие типу стены и этажу. Не подменять неизвестное свойство геометрией или DWG-слоем.
3. Добавить соответствие в `BimWallService`, обновить DTO/описание MCP и тесты. Для `top_z` достаточно валидировать `top_z > base_z` и переводить его в `height`, если этот вариант API нужен.
4. Следующим отдельным этапом выбрать уклонные крыши, редактирование контуров или ещё одну группу из матрицы SDK.

Минимальный проверяемый вызов MCP сейчас:

```json
{"name":"create_bim_wall","arguments":{"x1":0,"y1":0,"x2":6000,"y2":0,"base_z":0,"height":3300,"thickness":300}}
```

Ожидается `success: true`, `entity_type: "LinearBuildingWall"` и непустой `handle`.
Инструкции сборки и подключения DLL: [README.md](../README.md#2-установка-net-плагина).

Вызовы новых инструментов после загрузки свежей DLL (handle нужно взять из текущего DWG,
а `profile_name` — из результата `search_bim_library` для `concrete_profile`):

```json
{"name":"create_bim_association","arguments":{"master_handle":"A1","slave_handle":"A2"}}
{"name":"get_bim_associations","arguments":{"entity_handle":"A1"}}
{"name":"create_bim_concrete_beam","arguments":{"profile_name":"<точное имя профиля>","x1":0,"y1":0,"z1":3000,"x2":6000,"y2":0,"z2":3000}}
{"name":"create_bim_concrete_column","arguments":{"profile_name":"<точное имя профиля>","x1":0,"y1":0,"z1":0,"x2":0,"y2":0,"z2":3000}}
```
